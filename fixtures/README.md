# fixtures —— 快照与缓存

这个目录的存在是为了**让解析层和网络层解耦**。

## contract.cache.json

契约的本地缓存。`dojo.py` 每次成功拉到契约都会覆盖它；
靶场没起时自动退回读缓存（并在输出里打印警告）。

这样 `main.py --list` 这种"只想看看有什么"的操作不必先把服务起起来。

## snapshots/ —— HTML 快照

**一份快照 = 一次抓取 = 一个防护等级下的完整视野。**

```bash
python snapshot.py --level L3    # 自己起靶场、抓完、关掉 → fixtures/snapshots/l3/
python snapshot.py --all         # 六个等级各一份（约 1 分钟，L2 那趟要等窗口）
python snapshot.py --list        # 看已经有哪些

python main.py --snapshot auto    # 离线跑：每个实验各用自己那一级
python main.py --snapshot l3      # 离线跑：全部对着 l3 那一份
```

抓完之后，第 2、3、6、7、9 章**不用靶场也能跑** ——
`python main.py --snapshot auto` 在没有任何服务在跑的情况下能过 7 项。

> **顺带解决了一个老大难。** 靶场是"防护叠加"的：`--level all` 下裸 UA 在 L1 就停下，
> 第 6、7 章永远收不到那个请求，只能跳过。所以在线跑 `--level all` 是 6 通过 / 5 跳过，
> 而离线 `--snapshot auto` 是 **7 通过 / 4 跳过** —— 反而更多。
>
> 因为一份快照集合等价于"六台同时跑着的靶场"，每个实验找自己那一级说话。
> 这不是作弊：叠加是**一个进程只能配一套守卫**这个实现细节的产物，
> 不是防护本身的性质。想让读者逐级看现象，本来就该按等级分别取响应。

### 为什么"一份"要按等级分

因为同一路径在不同等级下返回**完全不同的东西**：

| 身份 | L0 | L1 | L3 | L4 | L5 |
| --- | --- | --- | --- | --- | --- |
| `whitelist` | 真内容 | 真内容 | 真内容 | 真内容 | 真内容 |
| `bare` | 真内容 | 403 | **蜜罐假数据** | **空壳** | 403 |
| `browser` | 真内容 | 200（无白名单标记） | 蜜罐假数据 | 403 | 403 |

第一行是关键：**内容层与防护层是正交的。** 白名单身份跳过全部守卫，
所以它拿到的内容在任何等级下都一样 —— 这就是为什么第 2、3 章的快照
随便哪一份都能跑，而第 4、6、7 章必须用对应等级的那一份。

### 三种身份是主键的一部分

同一路径 x 不同身份 = 不同响应，所以索引键是 `(路径, 身份)`：

| 身份 | 请求长什么样 | 会被怎么对待 |
| --- | --- | --- |
| `bare` | 没有 UA（requests 会填上自己的默认值） | 敲门就自报家门，L1 冲它来的 |
| `browser` | `Mozilla/5.0 ... Chrome/122` | 能过 L1，但**拿不到白名单标记** |
| `whitelist` | `DojoBot/1.0 (+https://blog.djdj45.top/about.html)` | 跳过 L1–L5 |

身份定义在 `dojo.py`（`IDENTITIES` / `headers_for`），抓取侧和读取侧共用一套 ——
少了任何一列，第 4 章那个"能过 ≠ 被接纳"的对照就复现不出来。

### manifest.json 里存了什么

除了每个文件的路径、状态码、响应头、sha256，还有两样容易被忽略的东西：

- **抓取时的完整契约**（含 `runtime.active_levels`）。
  离线模式直接拿它当契约用 —— 于是 `require("L3")` 检查的"当前生效等级"
  就是快照抓取时的等级，语义完全对得上，**不需要给离线模式写第二套判断逻辑**。
- **`r.encoding` / `r.apparent_encoding` 的观察值**。
  第 1 章讲的正是"r.text 为什么会乱码"，这两个值是观察结果，不记就复现不了那一课。

### 为什么快照不进仓库

三条理由，按重要性排：

1. **会过期，而且是静默地过期。** 靶场的模板一改，旧快照就和靶场对不上了；
   而解析实验对着过期页面报"通过"，比失败更糟。不提交 = 每次都得抓新的 = 永远同步。
2. 它们能从公开的靶场重新抓回来，一条命令的事。
3. 提交了会长得很快，而且 review 时是一堆噪音。

> 反过来说，如果你希望"克隆 crawler-labs 但不克隆 crawler-dojo 也能跑第 2、3 章"，
> 那提交一份最小快照（只有 whitelist 身份的那几页）是合理的 ——
> 两仓的 README 现在都假设你会把两个都克隆下来，所以这里选了不提交。
> 这个取舍是可以改的，改的话记得同时改 `.gitignore` 和这一节。

### 已知的时效性坑

蜜罐的假日期是 `date.today() + 9 天` 生成的。所以一份 l3 快照放十几天之后，
那些"未来日期"会自然变成过去，第 6 章的 F1 就不再成立。

这不是 bug，是**快照会过期**的真实样子。为了不让读者误判成"校验方法失效了"，
`lab06` 在离线模式下用**快照的抓取日**做基准（`ctx.reference_date`）——
判定的是"在观察到它的那一刻，这个日期是不是在未来"，语义上也更准确。
