# fixtures —— 快照与缓存

这个目录的存在是为了**让解析层和网络层解耦**。

## contract.cache.json

契约的本地缓存。`dojo.py` 每次成功拉到契约都会覆盖它；
靶场没起时自动退回读缓存（并在输出里打印警告）。

这样第 3 章（解析）可以脱离靶场单独跑，不必为了解析一段 HTML 先把服务起起来。

## HTML 快照（还没接进来）

计划是：抓取层把原始 HTML 存成 `fixtures/<slug>.html`，解析层只读快照。

好处有三条，都很实在：

1. **离线可跑** —— 解析代码的调试不该依赖网络
2. **快且稳** —— 一天跑一百次解析也不会打自己的服务器
3. **可复现** —— 页面改版后，旧快照还能用来复现历史上的解析 bug

这也是唯一能安全地对"别人的站"做解析测试的方式：抓一次，之后都对着快照。
不要把快照提交进仓库（`.gitignore` 里已经排除了 `fixtures/*.html`）——
它们是别人的内容，而且体积会长得很快。
