## 6.2 四种机械可判的校验

**机制**

识破蜜罐靠的不是火眼金睛，是**校验**。关键在于：好的校验必须是
**机械可判**的——不依赖领域知识，只依赖算术和日期。四种：

| # | 校验 | 判断标准（先口述一遍再往下看代码） |
|---|---|---|
| F1 | 时间范围 | 发布日期不能晚于今天——网站不可能有"明天发布的文章" |
| F2 | 重复率 | 一批文章里正文完全相同的占比异常高 → 数据源有问题 |
| F3 | 链接可达性 | 列表里给的详情链接，点开应该是 200——死链说明列表是假的 |
| F4 | 字段自洽 | `word_count` 与正文实际长度应大致相符——虚标 5 倍就是谎言 |

四条没有一条是"反爬技巧"，全是**数据工程的常识**。蜜罐有效，
恰恰因为它攻击的不是你的技术，是你的懒惰——你信任了服务端给的字段。
接下来两节把 F1、F2 各写成一个函数，F3、F4 你来组装。

## 6.3 `date.fromisoformat()` —— F1 时间范围

**它是什么**

```python
datetime.date.fromisoformat("2026-10-09") → datetime.date(2026, 10, 9)
```

把 `"YYYY-MM-DD"` 字符串变成日期对象。变成日期对象才能做**日期比较**——
字符串比较 `"2026-1-01" > "2026-09-30"` 会得出错误结论（字典序里 "1" > "0"），
而日期对象比较的是真实的先后。

**最小例子**

```python
import datetime as dt

today = dt.date.today()
print("今天:", today)

for d in ("2026-06-11", "2026-10-09"):
    published = dt.date.fromisoformat(d)
    print(d, "晚于今天吗 ->", published > today)
```

输出：

```
今天: 2026-09-30
2026-06-11 晚于今天吗 -> False
2026-10-09 晚于今天吗 -> True
```

**应用到这一批数据**：

```python
future = [a for a in items if dt.date.fromisoformat(a["published_at"]) > today]
print(f"{len(future)}/{len(items)} 条的日期晚于今天")
```

输出：

```
8/8 条的日期晚于今天
```

**8 条全是未来日期。** 一条数据可能是时钟问题，8 条全是——那是有人编的。
日期编造者只敢往未来编（往过去编容易和真数据撞车），
而"未来日期"恰好是最脆的破绽：**过了今天它就自动失效**。
这就是为什么校验要用"观察那一刻"的今天，而不是写死的日期。

**你来试试**

用第 2 章基线卡的日期范围（2026-03-04 → 2026-06-11）再写一道检查：
不在这个区间内的条数。两个检查（"不晚于今天" + "在基线范围内"）
哪个更严格？各自能拦住什么、拦不住什么？

## 6.4 `set()` 判重 —— F2 重复率

**它是什么**

Python 内置的集合类型：**元素不重复**。把 8 个正文各自算一个指纹
（sha1 摘要——第 9 章细讲，现在只知道"同一内容得到同一指纹"），
扔进 set，看还剩几个：

**最小例子**

```python
import hashlib

digests = {hashlib.sha1(a["body"].encode("utf-8")).hexdigest() for a in items}
print(f"{len(items)} 条正文 -> {len(digests)} 个不同指纹")
```

输出：

```
8 条正文 -> 1 个不同指纹
```

**8 条"不同的文章"，正文是同一段字。** 集合推导式（外面一层 `{}`）
把重复的全部合并——剩下的数量就是"真正不同的内容"数量。
`len(items)` 和 `len(digests)` 差得越多，数据越假。

为什么用 sha1 指纹而不是直接比较字符串？因为正文可能很长，
指纹只有 40 个字符——存得下、比得快，而且内容差一个字指纹就完全不同。
第 9 章入库时还会再见到它。

**你来试试**

用同样的方法算**标题**的重复率（把 `a["body"]` 换成 `a["title"]`）。
再对白名单身份拿到的 6 条真数据各算一次正文指纹——应该是 6 个不同值。
"重复率"只有配上"正常值长什么样"才有意义，这就是基线。

## 6.5 组装 `is_trustworthy()` —— 基线回归成武器

**它是什么**

把四条校验组装成一个函数。F3（链接可达）和 F4（字段自洽）你没写过，
照下面的样子补上——然后这份代码就是你的了：

```python
import datetime as dt

def is_trustworthy(article, today, base_url):
    problems = []
    # F1 时间范围
    if dt.date.fromisoformat(article["published_at"]) > today:
        problems.append("未来日期")
    # F4 字段自洽
    real = len(article["body"])
    if real and article["word_count"] > real * 3:
        problems.append(f"字数虚标（声称 {article['word_count']}，实际 {real}）")
    # 其余两条在批量层面做（F2）和请求层面做（F3），见下
    return problems
```

F4 的判据是"声称值超过实际 3 倍"——测一下这批数据：
`word_count` 声称 330，正文实际 66 个字符，**5 倍**，稳稳出界。

F3 要发请求（探测详情页可达性），所以它在批量检查里单独做：

```python
probe = requests.get(base_url + items[0]["url"])
print(probe.status_code)     # 404 —— 列表说有这篇文章，站点说没有
```

输出：

```
404
```

列表页热情地介绍了 8 篇文章，详情页一篇都不存在——**数据源自己拆穿了自己**。

**正确姿势**（最终形态，批量校验）：

```python
def check_batch(items, today, base_url):
    """返回破绽清单。空列表 = 通过。"""
    findings = []
    today_s = today.isoformat()
    findings += [f"未来日期: {a['slug']}" for a in items
                 if a["published_at"] > today_s]
    digests = {hashlib.sha1(a["body"].encode()).hexdigest() for a in items}
    if len(digests) < len(items) / 2:
        findings.append(f"正文重复: {len(items)} 条只有 {len(digests)} 种")
    return findings

findings = check_batch(items, dt.date.today(), "http://127.0.0.1:8000")
print(*findings, sep="\n")
```

跑出来你会看到未来日期 8 条 + 重复 1 条的完整清单。
**第 2 章你记基线时可能觉得多余**——自己的网站给的数能有什么问题？
现在这张卡拦下了一整批假数据。第 9 章它还会再上岗一次：
在**写入数据库**的位置把蜜罐挡在门外。

**你来试试**

把 `check_batch` 补上 F4（逐条检查字数虚标），然后：
① 对蜜罐的 8 条跑 → 全部拦下；② 对白名单的 6 条跑 → 清单为空。
两个结果都对，你的第一道数据防线就建成了。
