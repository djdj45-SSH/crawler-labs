# 第 3 章 · 解析：网页不是 JSON

> **第一部分 第一性：网页就是数据（3/3）**
> 上一章的数据是接口直接递过来的 JSON。这一章换硬骨头：**只有一个网页**。
> 你要从 HTML 里把同样的 6 条数据拆出来——读完本章，
> "发请求 → 读响应 → 解析成表"这条最小闭环就完整了。

### 开工前

```bash
pip install beautifulsoup4 lxml
```

两个包，一个分工：`beautifulsoup4`（简称 bs4）是**操作界面**，
`lxml` 是**解析引擎**。界面负责让你用顺手的方式查网页，引擎负责把乱糟糟的
HTML 真正拆开。照常，靶场保持运行（第 1、2 章怎么起的，这章还怎么起）。

import requests

状态码还是 200，但 `content-type` 变了：`text/html`。

## 3.1 为什么真实站点常只有 HTML

**机制**（这一节没有新函数，只有一张地图）

第 2 章那个 `/api/articles` 是靶场送的**理想情况**——数据加好工、摆好盘。
真实世界的网站，绝大多数时候你只会拿到一个网页：浏览器显示出来的每一段文字，
都是 HTML 标签包着的数据。打开主页，一条文章在源代码里长这样：

```html
<li>
  <a href="/posts/dojo-01-baseline.html">DOJO-1 基线读数：先确认它没坏</a>
  <div class="meta">2026-03-04 · 412 字</div>
  <div class="tags"><span class="tag">baseline</span><span class="tag">sensor</span></div>
  <p class="summary">上电后的第一件事不是接传感器，是把裸机的读数打出来。</p>
</li>
```

数据没少：标题在 `<a>` 里、日期和字数在 `class="meta"` 的 `<div>` 里、
标签在几个 `<span class="tag">` 里。**网页就是数据，只是包了一层壳，壳的名字叫标签。**
所谓解析，就是把壳拆掉、把数据按字段取出来。

从这章起你还需要一个新反射：看网页时要能切换到"源代码视角"。

**你来试试**

浏览器打开 `http://127.0.0.1:8000/`，右键 →「查看网页源代码」，
找到上面这段 `<li>`（Ctrl+F 搜 `dojo-01`），数一数一共有几条 `li`。

## 3.2 `BeautifulSoup(html, "lxml")` —— 把网页变成可查的对象

**它是什么**

```python
BeautifulSoup(html文本, 解析器名)
```

bs4 的主入口：把一整页 HTML 字符串拆开，还给你一个能按标签名、
按选择器查东西的对象，大家习惯命名为 `soup`。

**最小例子**

```python
import requests
from bs4 import BeautifulSoup

r = requests.get("http://127.0.0.1:8000/")
soup = BeautifulSoup(r.text, "lxml")
print(type(soup).__name__)
print(soup.title.get_text(strip=True))
```

输出：

```
BeautifulSoup
DOJO-1 调试笔记 · crawler-dojo
```

读法：`r.text` 是 3709 个字符的一整根字符串；`soup` 是拆好的房子——
每个标签都成了能按名字取的部件。`soup.title`、`soup.h1` 这种"按名字直接取"
适合取只出现一次的东西（页面标题、大标题）。

**参数**

只讲两个。第一个是 HTML 文本（`r.text`，也可以传 `r.content` 字节，第 1 章的区别还记得吗）。
第二个是解析器名：`"lxml"` 要单独安装（`pip install lxml`），快、容错好，是首选；
`"html.parser"` 是 Python 自带的备胎，不用安装，慢一点。

**会怎么摔（本章摔跤点 ①）**

解析器名写错了、或者 lxml 忘了装：

```python
soup = BeautifulSoup(r.text, "lxml")   # 没装 lxml 时
```

traceback 很长，最后一句是：

```
bs4.exceptions.FeatureNotFound: Couldn't find a tree builder with the features
you requested: lxml. Do you need to install a parser library?
```

读法：`FeatureNotFound` 是 bs4 在说"你点名的解析器我没找到"。
`Do you need to install a parser library?` 已经把药方开好了——
`pip install lxml`，装完重跑就好。

**你来试试**

把 3.2 最小例子里的 `"lxml"` 换成 `"html.parser"` 跑一遍，确认结果一样；
再故意写一个不存在的解析器名（比如 `"superfast"`），读一遍报错。

## 3.3 `soup.select("css 选择器")` —— 返回列表

**它是什么**

```python
soup.select(选择器) → [标签, 标签, ...]
```

传一个 **CSS 选择器**，返回**所有**匹配的标签，装在列表里。
CSS 选择器是前端给网页"设计样式"用的那套地址语法——
`.meta` 表示"所有 class 为 meta 的标签"、`ul li` 表示"ul 里面的 li"。
前端拿它做装修，你拿它做定位。

**最小例子**

```python
items = soup.select("ul li")
print(len(items))
```

输出：

```
6
```

**本章最重要的一次训练：先预测，再运行。**
三个选择器，先把预测的行数写在纸上，再跑：

```python
print(len(soup.select("a")))      # 预测：__？
print(len(soup.select("ul li")))  # 预测：__？
print(len(soup.select(".tag")))   # 预测：__？
```

实际输出：

```
8
6
12
```

对答案：

- `"a"` 是 **8**，不是 6——6 个文章链接之外，**页脚还有 2 个**（数据接口、契约）。
  选择器太宽，把不要的也圈进来了；
- `"ul li"` 是 **6**——范围圈死在文章列表里，一条不多；
- `".tag"` 是 **12**——每条 2 个标签，6 × 2。

**会怎么摔**

这一节的摔法**不是报错**，是悄悄给你 8 行——多出来的 2 行会在你取字段时
变成 None（3.4）或者干脆混进数据里。HTML 解析里最危险的错误全都**不报错**，
所以记住这条选择器的选法纪律：**越具体越安全。**

**你来试试**

跑 `"li a"` 和 `".summary"`，先在纸上写预测的行数，再运行对照。
预测错了不要紧——把"我为什么预测成那个数"想明白，比预测对了更重要。

## 3.4 `soup.select_one(...)` —— 返回一个，或 None

**它是什么**

```python
soup.select_one(选择器) → 第一个匹配的标签 | None
```

同一个选择器语法，只还**第一个**匹配；一个都匹配不到就还 `None`。
从列表项里取字段，用的都是它。

**最小例子**

```python
first = items[0]
print(first.select_one("a").get_text(strip=True))
print(soup.select_one("nav"))
```

输出：

```
DOJO-1 基线读数：先确认它没坏
None
```

第一行：`items[0]` 是一条 `li`，`select_one("a")` 在**它内部**找第一个 `<a>`——
`select_one` 不只 soup 能用，任何标签对象都能用，查找范围就是它自己内部。
第二行：页面里根本没有 `<nav>`，于是安静地给 None，**不报错**。

**会怎么摔（本章摔跤点 ②）**

None 自己不炸，炸在**你用它的时候**：

```python
nav = soup.select_one("nav")
nav.get_text()          # 页面里没有 nav，nav 是 None
```

```
Traceback (most recent call last):
  File "parse.py", line 9, in <module>
    nav.get_text()
    ^^^^^^^^^^^^
AttributeError: 'NoneType' object has no attribute 'get_text'
```

读法：`'NoneType' object has no attribute 'X'` = **你对着 None 调了 X**。
None 从哪来的？十有八九是 `select_one` 没找到东西。

它和第 2 章的 KeyError 是一对兄弟：

| | 取不到时 | 什么时候炸 |
|---|---|---|
| `a["key"]`（字典） | KeyError | **当场** |
| `select_one` 后调方法 | AttributeError | **延迟**——炸在你下一次使用它 |

延迟炸比当场炸难查得多——出错的行和出错的因隔了好几行。
所以下一节的纪律，在 HTML 这边比 JSON 那边更重要。

**你来试试**

跑 `soup.select_one("footer nav")`（必然 miss），先 `print` 它确认是 None，
再随便调它的一个方法，把 traceback 读一遍：炸的行是哪一行？None 是哪一行给的？

## 3.5 `get_text(strip=True)` —— 拿干净的文字

**它是什么**

一个标签里往往不止一层内容，`get_text()` 把它**所有后代**的文字拼成一串还给你；
`strip=True` 顺手把每段文字两头的空白剪掉。

**最小例子（对整条 `li` 做，别对 `.meta` 做——马上讲为什么）**

```python
print(repr(first.get_text()))
print(repr(first.get_text(strip=True)))
```

输出：

```
'\nDOJO-1 基线读数：先确认它没坏\n2026-03-04 · 412 字\nbaselinesensor\n上电后的第一件事不是接传感器，是把裸机的读数打出来。\n'
'DOJO-1 基线读数：先确认它没坏2026-03-04 · 412 字baselinesensor上电后的第一件事不是接传感器，是把裸机的读数打出来。'
```

`repr()` 会把字符串里的换行显示成 `\n`，所以能看清两次输出的真实样子。
这一版实验信息量很大，两个发现：

1. 不加 strip：换行、缩进全在。**HTML 里的空白是写网页的人排版用的，不是数据**；
2. 加了 strip：空白没了，但注意 `baselinesensor`——两个标签被**捏在一起**了。
   `get_text` 会把所有后代的文字直接拼接，标签之间的边界消失。

结论：整块 `get_text()` 只适合"看一眼里面有什么"；**真取字段，一个标签一取**：

```python
print(first.select_one("a").get_text(strip=True))              # 标题
print(first.select_one(".meta").get_text(strip=True))          # 日期 · 字数
print([t.get_text(strip=True) for t in first.select(".tag")])  # 标签列表
```

输出：

```
DOJO-1 基线读数：先确认它没坏
2026-03-04 · 412 字
['baseline', 'sensor']
```

第三个用了 3.3 的 `select`：标签天然是多个，取回来就该是列表——
这行是"列表推导式 + select + get_text"三个旧知识的一次合体。

**你来试试**

取 `.summary` 的文字（一个标签一取）；再把 `strip=True` 去掉，
用 `repr()` 看看多出来的是什么。

## 3.6 纪律：先断言行数，再取字段

**它是什么**

一个习惯，不是函数。第 2 章"先数数"在 HTML 里的加强版：

**HTML 解析的失败全是静默的。** 选择器写错、页面改版、数据根本不在这个页面——
给你的都是"0 行"或者"少几行"，**没有报错**。不检查就直接取字段，
错误会一路流进你的数据里（3.3 的 8 行、3.4 的 None，都是这么混进来的）。

**正确姿势**

```python
rows = soup.select("ul li")
if len(rows) != 6:                    # 6 来自第 2 章的基线卡
    print("行数不对劲:", len(rows), "—— 停，别往下取字段")
    exit(1)
```

**然后故意摔一次**（验证自己的检查真的接得住）：

```python
bad = soup.select("article")          # 故意写错的选择器
print(len(bad))
if not bad:
    print("守住了：0 行就停，不往下取字段")
```

输出：

```
0
守住了：0 行就停，不往下取字段
```

现在你的脚本有了"自检"：页面改版、选择器失效，它会在**最前面**停住并告诉你行数，
而不是往后吐出一堆空字段。

**第 7 章伏笔**：到时候你会遇到更邪门的情况——页面结构没变、选择器也没错，
行数却是 0。那是数据根本不在 HTML 里。今天先把"0 行就停"练成本能。

**你来试试**

把 3.7 脚本里的 `"ul li"` 故意改成 `"div li"`，运行，确认你的检查在
`select_one` 炸出 AttributeError **之前**把它拦了下来。

## 3.7 综合：标题和日期，拆成一张表

把 3.2–3.6 串起来，十行：

```python
import requests
from bs4 import BeautifulSoup

r = requests.get("http://127.0.0.1:8000/")
assert r.status_code == 200, r.status_code

soup = BeautifulSoup(r.text, "lxml")
rows = soup.select("ul li")
assert len(rows) == 6, f"行数 {len(rows)} != 基线 6"

for li in rows:
    title = li.select_one("a").get_text(strip=True)
    meta  = li.select_one(".meta").get_text(strip=True)
    date  = meta.split("·")[0].strip()   # '2026-03-04 · 412 字' → '2026-03-04'
    print(f"{date}  {title}")
```

输出：

```
2026-03-04  DOJO-1 基线读数：先确认它没坏
2026-03-19  串口丢字符：帧间隔比波特率更重要
2026-04-02  CRC 选了 CRC-8 而不是 CRC-16 的理由
2026-04-21  温漂：不是传感器的问题，是参考电压的问题
2026-05-08  日志压缩：把重复的帧头干掉
2026-06-11  导出链路：为什么最终选了裸流而不是 CSV
```

和第 2 章那张表逐字对照——**同一家店，两种货架，同一批货**。
第 2 章的货摆在 JSON 接口上，这一章的货摆在 HTML 里，拆下来一模一样。
新东西只有一处：`meta.split("·")`——`meta` 的原文是 `"2026-03-04 · 412 字"`，
按 `·` 切开取前半段，再把空白剥掉（`strip` 的老本行），剩下的就是日期。

到这里，第一部分承诺的闭环全部兑现：**发请求 → 读响应 → 解析成表**。
从下一章起，靶场不再这么客气了。
