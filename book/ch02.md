## 90 秒现象

新建 `crawl.py`：

```python
import requests

r = requests.get("http://127.0.0.1:8000/api/articles")
items = r.json()
print(r.status_code, type(items).__name__, len(items))
```

运行：

```
$ python crawl.py

```

一行三个数，每个都有用：**状态码 200**（门开了）、**类型是 list**（数据是一批，
不是一条）、**一共 6 条**。这 6 条就是这个练习网站的全部文章。

## 2.2 `len()` —— 先数数，再看货

**它是什么**

Python 内置函数：数一个"装了东西的东西"里有多少件。字符串、列表、字典都能数。

**最小例子**

```python
print(len(items))        # 6
print(len(items[0]))     # 6 —— 第一条字典有 6 个键
print(len(first["tags"]))# 2 —— 第一条有 2 个标签
```

**为什么值得单独一节**

爬虫里 `len()` 不是工具，是**体检**。养成一个条件反射：
拿到一批数据，**第一件事数一数**。0 条意味着选择器错了或接口变了
（第 3、7 章你会两次靠这个反射救命）；条数突然变多意味着你可能拿到了假数据
（第 6 章的蜜罐就干这事）。

**你来试试**

在 2.1 的脚本里把 `len(items)` 的结果和一个预期的数字比较，
条数不是 6 就打印"数据不对劲"。这个 6，就是你写下的第一行**基线**。

## 2.3 `a["key"]` 与 `a.get("key")` —— KeyError 第一课

**它是什么**

取字典里值的两种写法，和 1.3 的 headers 一模一样的分野：

- `a["slug"]` —— 键不存在，**当场 KeyError**
- `a.get("slug")` —— 键不存在，**安静地给 None**

**会怎么摔（本章的精选摔跤点）**

```python
first["no_such_key"]
```

报错原文：

```
KeyError: 'no_such_key'
```

KeyError 是全书出场率最高的报错。读法固定：**冒号后面的引号里就是缺的键名**。
它几乎总在说同一件事：**你以为数据里有的字段，其实没有**——要么键名拼错了，
要么这个网站的结构和你想的不一样。

**怎么选**

- **必须有**的字段（没有这条数据就是废的）：用 `a["slug"]`，让它报错。
  错误在**你眼前**爆炸，好过 `None` 流进数据库。
- **可有可无**的字段：用 `a.get("remark")`，拿到 None 自己决定怎么办。

一句话：**报错是你的朋友，静默的 None 才是敌人。**

**你来试试**

分别用两种写法取 `first["word_count"]` 和 `first["author"]`（这个键不存在），
观察两种结果。哪种写法让错误当场炸出来？

## 2.4 列表推导式 —— 一行取一列

**它是什么**

Python 的招牌语法：**"对列表里每个元素做同一件事，收集成新列表"**。
爬虫天天用——"从 6 条数据里把所有标题拿出来"就是它的本职。

**最小例子**

```python
titles = [a["title"] for a in items]
for t in titles:
    print(t)
```

输出：

```
DOJO-1 基线读数：先确认它没坏
串口丢字符：帧间隔比波特率更重要
CRC 选了 CRC-8 而不是 CRC-16 的理由
温漂：不是传感器的问题，是参考电压的问题
日志压缩：把重复的帧头干掉
导出链路：为什么最终选了裸流而不是 CSV
```

读法：`for a in items` 轮流拿出每条，`a["title"]` 提出标题，方括号把 6 个标题
装回一个新列表。等价的普通写法要四行：

```python
titles = []
for a in items:
    titles.append(a["title"])
```

两种写法完全等价。推导式值得学是因为**它在真实代码里出现的频率太高**，
别人写 `for` 循环的地方，十有八九是一行推导式。

**你来试试**

用一行推导式取出所有 `published_at`；再用一行取出 `word_count` 大于 400 的
那些条目的标题（提示：推导式可以带 `if`：`[a["title"] for a in items if ...]`）。

## 2.5 `for` + 格式化 —— 把数据摆成一张表

**它是什么**

数据拿全了，最后一步是**摆出来看**。f-string 的对齐语法
（`{值:>宽度}` 靠右、补空格）能把杂乱的输出变成能扫一眼的表。

**最小例子**

```python
for a in items:
    print(f"{a['published_at']}  {a['word_count']:>4} 字  {a['title']}")
```

输出：

```
2026-03-04   412 字  DOJO-1 基线读数：先确认它没坏
2026-03-19   386 字  串口丢字符：帧间隔比波特率更重要
2026-04-02   455 字  CRC 选了 CRC-8 而不是 CRC-16 的理由
2026-04-21   398 字  温漂：不是传感器的问题，是参考电压的问题
2026-05-08   372 字  日志压缩：把重复的帧头干掉
2026-06-11   430 字  导出链路：为什么最终选了裸流而不是 CSV
```

日期对齐、字数对齐——因为 `:>4` 让 372 和 455 都占 4 格。
第 9 章会把这张表存进数据库；在那之前，**能打印成表就够用**。

**你来试试**

给表格加一列 `tags`（提示：`",".join(a["tags"])` 能把标签列表拼成字符串）。

## 2.6 基线 —— 把"正常长什么样"记下来

**它是什么**

一个习惯，不是函数：**在一切正常的时候，把数据的形状记下来。**

为什么？因为"不对劲"没法凭空判断——你先得知道"对劲"长什么样。
第 6 章有个经典的陷阱：状态码 200、结构完整、字段齐全，**但每一条都是假的**。
识破它靠的不是火眼金睛，就是这一节记下的基线。

**照抄这张卡，填满后存好（真的存，第 6 章要用）：**

```
┌─ 基线记录卡 · /api/articles ──────────────────┐
│ 条数      6                                    │
│ slug 形状 dojo-0x-短横线单词                    │
│           （如 dojo-01-baseline）              │
│ 日期范围  2026-03-04 → 2026-06-11              │
│ 字数范围  372 – 455                            │
│ 标签全集  baseline, calibration, data, debug,  │
│           firmware, hardware, protocol,        │
│           python, sensor, serial, storage      │
│           （11 个）                            │
└────────────────────────────────────────────────┘
```

**正确姿势**

基线卡不是抄完就完。把"检查基线"写成一个函数，每次抓完自动体检：

```python
def looks_normal(items):
    checks = [
        (len(items) == 6,                       f"条数 {len(items)} != 6"),
        (all(a["slug"].startswith("dojo-") for a in items), "slug 形状不对"),
        (all(370 <= a["word_count"] <= 460 for a in items), "字数出界"),
    ]
    bad = [msg for ok, msg in checks if not ok]
    return bad          # 空列表 = 一切正常
```

现在它看起来多余——数据是你自己的网站给的，怎么会不对劲？
**记住这个疑问，第 6 章揭晓。**
