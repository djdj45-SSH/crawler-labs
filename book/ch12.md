## 12.1 `RobotFileParser` —— robots.txt 是机器可读的礼貌

**它是什么**

`urllib.robotparser` 标准库里的 robots.txt 解析器：读一份站点声明，
回答"我这个客户端能不能抓这个 URL"。**每次爬一个新站点，先过它**——
这是行业公约，不是法律条文，但全行业的爬虫框架默认遵守（第 8 章
`ROBOTSTXT_OBEY = True` 是 Scrapy 的出厂默认值）。

**最小例子**（拿第 10 章抓过的博客 robots.txt）：

```python
import requests
from urllib.robotparser import RobotFileParser

UA = {"User-Agent": "DojoBot/1.0 (+https://blog.djdj45.top/about.html)"}
text = requests.get("https://blog.djdj45.top/robots.txt", headers=UA).text

rp = RobotFileParser()
rp.parse(text.splitlines())

for path in ("/posts/boot-log.html", "/traps/trap-python", "/sitemap.xml"):
    url = "https://blog.djdj45.top" + path
    print(f"{path:24} ->", rp.can_fetch("*", url))
```

输出：

```
/posts/boot-log.html     -> True
/traps/trap-python       -> False
/sitemap.xml             -> True
```

对照第 10 章读过的 robots.txt 原文：文章和 sitemap 放行，
`/traps/`、`/blocked/` 禁抓——**网站把"哪些给我抓、哪些别碰"写成了机器可读的合同**，
`can_fetch()` 就是按这份合同办事。注意博客 robots.txt 里的那句原文：
"本站欢迎爬虫，条件是它肯说明自己是谁"——合同是双向的。

**会怎么摔**

robots.txt 不存在时（404），按公约视为**全部允许**；
但请求失败（超时、5xx）时，保守的做法是**视为不允许**，稍后再试。
另外 robots.txt 是"请勿进入"的门牌，不是墙——它拦君子不拦技术，
**它对你的约束力来自你自己的决定**。这正好引出下一节。

**你来试试**

用 `can_fetch` 把博客的 15 篇文章清单（第 10 章的）全部过一遍，
确认没有一条撞上 `Disallow`。这是每次真实爬取前的固定动作。

## 12.2 频率礼仪 —— 把"别打太快"变成数字

**机制**

"别打太快"不是规则，是愿望。规则要能执行，就得有数字：

| 礼仪项 | 数字化 | 你已有的工具 |
|---|---|---|
| 请求间隔 | 每请求 ≥0.5s（真实站点建议 1s+） | 第 5 章 `time.sleep` / Scrapy `DOWNLOAD_DELAY` |
| 并发 | 单站点并发 ≤2，本教程用 1 | Scrapy `CONCURRENT_REQUESTS_PER_DOMAIN` |
| 限流响应 | 429 → 按 `Retry-After` 退避 + 抖动 | 第 5 章 `retry_get` |
| 时段 | 避开对方业务高峰（流量画像里看） | 抓取计划里写死 |
| 身份 | 每个请求都带 `YourBot/1.0 (+联系页)` | 第 4 章 |

再看一眼第 10 章的流水线：`time.sleep(0.5)` + 声明身份 + 总共 15 个请求。
**这些不是"写出来好看的"，是对一个真实服务器可感知的差别**——
你的博客日志里，DojoBot 的访问是规律的、可识别的、随时可联系的。

**你来试试**

给第 10 章的流水线加一条"访问预算"：单次运行总请求数不超过 20，
超了就停并报告。预算制是防止"再抓一页就好"失控的最好办法。

## 12.3 合规边界 —— 什么能抓，什么不能

**机制**（本节是一份清单，不是法律意见；拿不准时问专业人士）

| 维度 | 红线 | 说明 |
|---|---|---|
| 数据性质 | **个人数据不抓** | 手机号、身份证号、住址……与"公开可访问"无关 |
| 版权 | 大段**内容**搬运要授权 | 事实和标题可以聚合，正文转载是另一回事 |
| 服务条款 | 违反 ToS 的抓取风险自担 | 很多站点的 ToS 明文禁止自动化访问 |
| 技术边界 | **不破解、不绕过、不伪造** | 本书全部"通过"都是靠合规身份，不是靠绕过 |
| 影响对方 | 不给对方造成负担 | 12.2 的全部数字，落实到这里 |

本书的合规基础说清楚了三遍，这里最后一次：**靶场、博客都是作者自己的资产**，
公开练习站（books.toscrape 等）明文欢迎爬虫。所以书里每一次请求都站得住。
你自己的实践请保持同样的标准：**要么是你有权抓的，要么是明确欢迎你的。**

还有一个技术性的红线值得单独说：**防护规则可以公开，攻击代码不可以。**
本书教你读黑名单、算签名，是因为这些知识同时是"写防护"的知识（第 11 章）；
它不包含"绕过真实站点防护"的任何内容——那不是技术难度问题，是立场问题。

**你来试试**

给你自己定三句话的"爬虫章程"（身份怎么声明、频率多少、什么数据绝不碰），
写进你所有爬虫脚本的文件头注释。以后每次写新爬虫，先抄章程再写代码。

**先看那个"0"：失败 0。** 全书 12 章，所有实验对着全开的防护跑，零失败。

**再看那 5 个跳过**——它们不是意外，是本章最后的课程。实验 05/06/07/10
的跳过原因都是同一句话："请求被 **L1** 先生效拦下，到不了 L2/L3/L4/L5"。
**防护是叠加的**：全等级开启时，裸 UA 在第一道门就被拦下，永远到不了
后面的级别。这不是靶场的缺陷——真实站点就是这样，你根本不知道前面
还有几道门。所以按级实验要**单独开那一级**跑（`--level L2`……），
这也是本书每一章"开工前"让你换挡的原因。

对照另一条路：`python snapshot.py --all && python main.py --snapshot auto`
能把全部实验离线跑完（live_only 的除外）——离线模式和在线模式互为补充，
这就是全书反复强调的"响应当数据"的最终形态。
