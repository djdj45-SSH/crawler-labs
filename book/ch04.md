## 90 秒现象

还是第 2 章那个脚本，一个字不改：

```python
import requests

r = requests.get("http://127.0.0.1:8000/api/articles")
print(r.status_code)
```

输出：

```
403
```

**全书第一次失败。** 脚本没改过，改的是靶场——从 L0 换到 L1。
同一个 URL、同一台机器，昨天还是 200，今天 403。
把脚本从头到尾读三遍也找不出 bug，因为**问题不在你的代码里，在你发出去的身份上**。

requests 不设 User-Agent 时会自动填上 `python-requests/2.x`——
它诚实地告诉对方"我是 requests 库"。而 L1 的黑名单里，第一个名字就是它。

## 4.1 三种身份 —— "我是谁"是自变量

**机制**

从本章起，取页面多了一个维度。同一个 URL，同一时刻，带上不同的
`User-Agent` 去请求，会得到完全不同的响应。靶场把爬虫的身份分成三种：

| 身份 | User-Agent | 是什么 |
|---|---|---|
| `bare` | `python-requests/2.x`（requests 默认） | 没有声明身份——敲门时自报家门"我是 requests" |
| `browser` | 一段 Chrome 的 UA | 伪装成浏览器 |
| `whitelist` | `DojoBot/1.0 (+https://blog.djdj45.top/about.html)` | 声明身份 + 留联系方式 |

配套地，本书的实验套件从这章起改用一个统一的取页入口 `ctx.fetch()`：

```python
r = ctx.fetch(url, identity="bare")       # 在线打靶场，或离线读快照
r = ctx.fetch(url, identity="whitelist")
```

它就是 `requests.get` 加了一个**身份参数**——多出来的两个本事后面会讲到：
离线模式（快照）和契约感知（自动带上对应身份的请求头）。
本章课文先用裸 `requests` 把原理讲透，过关检查里你会见到 `ctx.fetch` 本尊。

三种身份各跑一次（就是 4.2 的 `headers` 参数，提前用上）：

```python
import requests

API = "http://127.0.0.1:8000/api/articles"
WHITELIST_UA = "DojoBot/1.0 (+https://blog.djdj45.top/about.html)"

for name, headers in [
    ("bare      ", {}),
    ("browser   ", {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                             "AppleWebKit/537.36 (KHTML, like Gecko) Chrome/122.0 Safari/537.36"}),
    ("whitelist ", {"User-Agent": WHITELIST_UA}),
]:
    r = requests.get(API, headers=headers)
    print(f"{name} {r.status_code}  X-Dojo-Block={r.headers.get('X-Dojo-Block')}  "
          f"X-Dojo-Allow={r.headers.get('X-Dojo-Allow')}")
```

输出：

```
bare        403  X-Dojo-Block=ua  X-Dojo-Allow=None
browser     200  X-Dojo-Block=None  X-Dojo-Allow=None
whitelist   200  X-Dojo-Block=None  X-Dojo-Allow=whitelist
```

先把这个表抄下来——4.4 要回答"为什么 browser 拿不到 X-Dojo-Allow"。

**你来试试**

把上面三种身份各跑一次。然后填空：`bare` 得到 ___，它的 `X-Dojo-Block`
的值是 ___（这个值 4.3 会用到）。

## 4.2 `requests.get(url, headers=...)` —— 请求头是自我介绍

**它是什么**

```python
requests.get(url, headers={"头名": "值", ...})
```

给请求附加自定义请求头。第 1 章 1.3 读过 `r.headers`（对方寄来的信封），
`headers=` 是**寄出去的信封**——你可以在里面写字，对方读不读、信不信是另一回事。

**最小例子**

```python
import requests

r = requests.get(
    "http://127.0.0.1:8000/api/articles",
    headers={"User-Agent": "my-first-crawler/0.1"},
)
print(r.status_code)
```

输出：

```
200
```

一个自己编的 UA 就过了 L1——因为它不在黑名单里。这个现象本身值得停下来想一想：
**"200" 只说明这一条规则放过了你**，它不代表你被信任。4.4 会证明这句话。

**会怎么摔**

`headers` 拼错键名不会报错：

```python
requests.get(url, headers={"user-agent ": "DojoBot/1.0"})   # 注意结尾多了个空格
```

403。没有任何提示告诉你为什么。请求头的键名要**一字不差**——
HTTP 头名不区分大小写（`User-Agent` 和 `user-agent` 等价），
但**多一个空格、少一个横线**就不是同一个头了。这类错误没有 traceback，
只有"我明明改了 UA 为什么还是 403"——排查方法是 4.4 的对照法：
把能过的 headers 和不能过的并排放，逐个字符比。

**你来试试**

自己编一个 UA（起个自己喜欢的名字），先预测靶场的反应，再运行。
把它改成 `python-requests/2.31.0` 再跑一次——同一个代码，只改一个字符串。

## 4.3 黑名单怎么工作 —— 开卷考试

**机制**

被 403 时别急着改代码，先读对方给你的两样东西。

第一样：**响应头里的信号**。

```python
r = requests.get("http://127.0.0.1:8000/api/articles")
print(r.headers.get("X-Dojo-Block"))     # ua
print(r.headers.get("X-Dojo-Level"))     # L1
```

输出：

```
ua
L1
```

`X-Dojo-Block: ua`——被"UA 检查"这一环拦下。真实站点不会有这么客气的头，
但"被拦时先看响应头和响应体"这个动作是通用的。

第二样：**403 页面本身**。它不是天书，读正文：

```
403 BLOCKED
这一级把你挡住了
拦截原因    User-Agent 命中黑名单：python-requests
改 UA 能过。但更好的做法是声明身份——请求头里带标识与联系方式的
客户端会被白名单放行，规则见 /__dojo/contract 的 whitelist 段。
```

它把拦截原因和出路都写了。而完整的规则表在契约里：

```python
import requests

c = requests.get("http://127.0.0.1:8000/__dojo/contract").json()
print(c["levels"]["L1"]["config"]["block"])
```

输出：

```
['python-requests', 'httpx', 'aiohttp', 'scrapy', 'curl', 'wget',
 'go-http-client', 'okhttp', 'java/', 'node-fetch', 'axios',
 'libwww-perl', 'python-urllib']
```

13 个名字，几乎覆盖了所有主流 HTTP 库和命令行工具的默认 UA。
**规则是公开的**——这是靶场和本书都坚持的设计：守方的规则一旦部署，
就该假设攻方迟早看得到（真实世界里，换个 UA 试三次就能摸出黑名单长什么样）。
所以靶场干脆开卷：考的不是"黑名单里有什么"，而是**你看到规则之后怎么做**。

**你来试试**

对照这 13 个名字，再找 3 个"你预计会被拦"的 UA（提示：想想还有哪些
语言和工具会发 HTTP 请求），写一个循环逐个试，验证你的预测。

## 4.4 伪装 vs 声明 —— 同一个 200，两种待遇

**机制**

回到 4.1 那张表，看 ② 和 ③ 的差别——它们都是 200，都能拿到 6 条数据，
但响应头里少了一个东西：

| | 状态码 | X-Dojo-Allow |
|---|---|---|
| ② 伪装浏览器 | 200 | **（无）** |
| ③ 声明身份 | 200 | `whitelist` |

`X-Dojo-Allow: whitelist` 是靶场在说："我认得你，你是声明过身份的那位。"
白名单身份会**跳过 L1 到 L5 全部防护**——这不是靶场开了后门，
而是全项目定义的礼貌爬虫约定（4.5）。

这两条路的本质区别：

- **伪装** = 在这一条规则上不再被针对。下一条规则（频率、行为、指纹……）
  还会瞄准你，因为你在对方眼里仍然是"来路不明的流量"。
- **声明** = 从对抗关系进入**被接纳状态**。对方知道你是谁、
  能联系到你，后续的规则可以主动放行你。

伪装的路走不到头：黑名单 13 个名字，你换掉一个 UA 就出局了，
但对方还有 12 个维度可以用。这也是第 5 章你会亲眼看到的——
**限流那一级，伪装完全没用**，因为它根本不看你是谁，只看你多快。

**你怎么知道一个 200 是"被接纳"还是" merely 没被拦"？**——
对照法：拿两种身份各请求一次，diff 它们的响应头。这个动作要练成本能，
第 10 章打真实站点时它就是你的主武器（那里连信号头都没有）。

**你来试试**

用伪装身份把 4.1 的表重跑一遍，确认 `X-Dojo-Allow` 一直拿不到；
再用声明身份跑，看它回来。然后把 browser 的 UA 改成带 `DojoBot`
字样的字符串——预测一下结果，再跑（提示：白名单的匹配规则在契约
`whitelist.contains` 里，是"包含 dojobot"，大小写不敏感）。

## 4.5 `DojoBot/1.0 (+联系方式)` —— 给爬虫起个正经名字

**它是什么**

一个习惯，不是一个函数。声明身份的 UA 有个通行写法：

```
DojoBot/1.0 (+https://blog.djdj45.top/about.html)
```

三段：**名字/版本 (+能核实你身份的页面)**。名字让人知道你是什么，
联系方式让人能找到你。契约里白名单的定义就一条：UA 里包含 `dojobot`。

为什么"留联系方式"这么重要？因为对方的反应取决于他能不能**联系你**：

- 你的爬虫太猛打挂了他的站，他能给你发邮件，而不是直接封 IP；
- 你抓的东西对他有用，他能反过来找你合作；
- 你出了 bug 死循环请求，他要能分辨"故障"和"攻击"。

反过来说，**不留联系方式的爬虫，对方只有一种安全的选择：当攻击处理。**

**正确姿势**

给你的爬虫起一个正式的名字，从第一个请求就带上：

```python
UA = "my-crawler/0.1 (+https://你的域名/about.html)"
headers = {"User-Agent": UA}
```

没有域名？GitHub 仓库链接也可以——要的是"能核实、能联系"。
别用别人的 UA（包括伪装成浏览器），那等于把自己的行为记在别人账上。

**你来试试**

给你的爬虫起名并声明：把上面那个 UA 里的名字换成你自己的，
跑通 `/api/articles`，确认拿到 `X-Dojo-Allow: whitelist`。
这个名字会陪你走完剩下的章节。
