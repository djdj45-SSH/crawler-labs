# 第 1 章 · 你的第一次请求

> **第一部分 第一性：网页就是数据**
> 这一部分跨过一道坎：把"我看到的网页"变成"我手里的数据"。
> 三章之后，你会拥有一个能跑的脚本：发请求 → 读响应 → 解析出一张表。

本章不出现"爬虫"这个词，也不谈任何防护。你只做一件事：
**向一个网站发一条消息，把它回给你的东西读明白。**

## 90 秒现象

新建 `first.py`，5 行：

```python
import requests

r = requests.get("http://127.0.0.1:8000/__dojo/contract")
print(r.status_code)
```

运行：

```
$ python first.py
200
```

`200` 是那个网站回给你的一句话，意思是"收到了，一切正常"。
你刚刚完成了一次完整的 HTTP 请求。本章剩下的所有内容，
都是在回答一个问题：**除了 `200`，它还回了我什么？**

---

## 1.1 `requests.get(url)` —— 发出一条消息

**它是什么**

`requests` 库里的头号函数：向 `url` 发一个 GET 请求，把网站的回复打包成一个
对象还给你。大家习惯把这个对象命名为 `r`（response 的首字母）。

```python
r = requests.get("http://127.0.0.1:8000/__dojo/contract")
```

**最小例子**

```python
import requests

r = requests.get("http://127.0.0.1:8000/__dojo/contract")
print(r)
print(type(r))
```

输出（对象里那串十六进制是内存地址，每次都会不一样，不用管）：

```
<Response [200]>
<class 'requests.models.Response'>
```

`<Response [200]>` 一行就说了两件事：我拿到了一个**回复**，回复的状态码是 **200**。

**参数**

`get()` 的完整参数表有二十多个。现在只需要认识第一个 `url`，
其余的先不管——**它们会在该出现的章节出现**（第 4 章你会认识 `headers`，第 5 章认识 `timeout` 的兄弟们）。

**会怎么摔**

`url` 写错会怎样？把域名换成一个不存在的：

```python
import requests

r = requests.get("http://no-such-host.example")
```

这次的输出不是 `200`，而是一整块红色的报错。别慌，**读它的最后一行**：

```
requests.exceptions.ConnectionError: HTTPConnectionPool(host='no-such-host.example', port=80):
Max retries exceeded with url: / (Caused by NameResolutionError("...Failed to resolve 'no-such-host.example'"))
```

最后一行的括号里写着 `Failed to resolve`——**域名解析失败**，互联网上根本查无此人。
从现在起养成一个习惯：**报错从最后一行往回读**，90% 的情况答案就写在那一行。

**你来试试**

把 `first.py` 里的域名改成一个不存在的（比如 `http://no-such-host.example`）。
**先在纸上写下你预测会看到什么**，再运行，对照。
然后改回来，确认又能看到 `200`。

## 1.2 `r.status_code` —— 先看门牌号

**它是什么**

回复对象身上的一个属性：这次请求的**结果编号**。它是个整数，直接比较就行。

| 编号 | 含义 | 一句话 |
|---|---|---|
| 2xx | 成功 | 门开了 |
| 3xx | 重定向 | "东西搬了，去那边" |
| 4xx | 你的问题 | 地址写错（404）或你不受欢迎（403，第 4 章的主角） |
| 5xx | 网站的问题 | 网站自己病了 |

**最小例子**

```python
import requests

r_ok = requests.get("http://127.0.0.1:8000/__dojo/contract")
r_bad = requests.get("http://127.0.0.1:8000/no/such/page")
print(r_ok.status_code, r_bad.status_code)
```

输出：

```
200 404
```

**会怎么摔**

`status_code` 不摔跤——它永远是整数。**摔跤的是不看它的人**：
拿到回复就急着读内容，404 的页面内容是"找不到"提示页，
你把提示页当数据解析，错误会静默地传到很远的地方。
所以本书的每一段代码都遵守同一条纪律：

```python
r = requests.get(url)
if r.status_code != 200:
    print("出事了：", r.status_code)
    exit(1)
```

**你来试试**

把 URL 改成 `http://127.0.0.1:8000/posts/dojo-01-baseline.html` 和
`http://127.0.0.1:8000/`，各跑一次，**先预测再运行**：这两个地址的状态码应该是什么？

## 1.3 `r.headers` —— 信封上写了什么

**它是什么**

回复的**头部信息**：内容是什么类型、多长、哪台服务器发的。
把它想象成信封——信（内容）还没拆，信封上已经印着"挂号信""来自某地"这些信息。

`headers` 的行为像一个字典：键是小写的字符串。

**最小例子**

```python
import requests

r = requests.get("http://127.0.0.1:8000/__dojo/contract")
print(r.headers.get("content-type"))
print(r.headers.get("server"))
print(r.headers.get("x-not-exist"))
```

输出：

```
application/json
uvicorn
None
```

**参数（取值的两种写法）**

- `r.headers["content-type"]` —— 键不存在时**当场报错**（和字典一样）
- `r.headers.get("content-type")` —— 键不存在时**安静地返回 None**

取头信息一律推荐 `.get()`：头信息本来就是"有则更好，没有也能活"的东西。

**你来试试**

打印 `list(r.headers.keys())`，把每个键名读一遍。
猜猜 `content-length` 是什么意思？它和 1.4 的什么东西对得上？

## 1.4 `r.content` / `r.text` / `r.encoding` —— 字节怎么变成文字

**它是什么**

真正的内容藏在两个属性里：

- `r.content` —— **原始字节**。互联网上传的就是它，它永远不会错
- `r.text` —— 字节**按某种编码解码后**的字符串。舒服，但依赖"某种编码"猜得对不对

`r.encoding` 就是 requests 替你猜的那个答案（来自响应头或它的默认值）；
`r.apparent_encoding` 是它看内容猜出来的另一个答案。

**最小例子**

```python
import requests

r = requests.get("http://127.0.0.1:8000/__dojo/contract")
print(r.encoding, r.apparent_encoding)
print(len(r.content))
print(r.text[:60])
```

输出：

```
utf-8 utf-8
4299
{"version":1,"name":"crawler-dojo","site":"DOJO-1 调试笔记","des
```

两个编码一致，`r.text` 完好。**但"一致"不是保证，是运气。**

**会怎么摔（本章第一个精选摔跤点，全书还会引用它）**

requests 的一个历史习惯：响应头没写编码时，它默认按 `ISO-8859-1` 解码——
那是一张只认识西欧字母的表，用它解中文就是灾难。亲手制造一次：

```python
print(r.content.decode("iso-8859-1")[:60])
```

输出：

```
{"version":1,"name":"crawler-dojo","site":"DOJO-1 è°è¯ç¬è®°","des
```

`è°è¯ç¬è®°` 就是"调试笔记"被错解后的尸检现场。**这不是库的 bug，是"替你做决定"的代价。**

**正确姿势**：不确定编码时，别信 `r.text`，信字节：

```python
text = r.content.decode("utf-8")     # 你自己指名用 utf-8
```

**你来试试**

把 `decode("iso-8859-1")` 换成 `decode("utf-8")` 再跑一遍，对照两行输出。
中文回来了——这两行的差别，就是 1.4 全部的内容。

## 1.5 `r.json()` —— 一条命令拿结构

**它是什么**

如果内容本来就是 JSON 文本（看看 1.4 的输出开头，那个 `{` 就是证据），
`r.json()` 一步把它变成 Python 的字典/列表。等价于
`json.loads(r.text)`，但更不容易在编码上栽跟头。

**最小例子**

```python
import requests

r = requests.get("http://127.0.0.1:8000/__dojo/contract")
doc = r.json()
print(type(doc).__name__)
print(list(doc.keys()))
```

输出：

```
dict
['version', 'name', 'site', 'description', 'why', 'whitelist', 'endpoints', 'data_flavor', 'levels', 'runtime']
```

一个字典。键名先扫一遍，不用懂——`endpoints` 和 `levels` 会在后面几节反复出现。

**会怎么摔（第二个精选摔跤点）**

`.json()` 只对 JSON 内容有效。对普通网页调它会怎样？

```python
import requests

r = requests.get("http://127.0.0.1:8000/")
r.json()
```

报错原文：

```
ValueError: Expecting value: line 1 column 1 (char 0)
```

这句话的意思是："我从第一个字符（char 0）开始就期待 JSON 的值，但第一列第一个字符就不是"——
因为那是 HTML 页，开头是 `<!DOCTYPE html>`。
**以后看到这个 ValueError，第一反应应该是：我要的东西可能不是 JSON。**

**你来试试**

打印 `doc["site"]` 和 `doc["data_flavor"]`，读一读这个练习网站对自己的介绍。

## 1.6 综合 —— 打印一份"网站地图"

契约 JSON 里有一个 `endpoints` 字段：这个网站所有的门牌。
把它打印出来——这是你第一个真正有用的爬虫动作。

```python
import requests

r = requests.get("http://127.0.0.1:8000/__dojo/contract")
if r.status_code != 200:
    print("出事了：", r.status_code)
    exit(1)

doc = r.json()
for name, path in doc["endpoints"].items():
    print(f"{name:<14} {path}")
```

输出：

```
contract       /__dojo/contract
health         /__dojo/health
index          /
list_json      /api/articles
detail_html    /posts/{slug}.html
js_payload     /static/dojo-data.js
```

注意 `list_json` 那一行——`/api/articles`。下一章我们就从这扇门进去，
把第一批数据拿回你家。
