## 10.1 现象：连 sitemap 都被改道了

**90 秒现象**

按老习惯，先抓站点地图（sitemap.xml）——这是爬虫的标准开场：

```python
import requests

r = requests.get("https://blog.djdj45.top/sitemap.xml")
print(r.status_code)
print("落点:", r.url)
print("有 <loc> 吗:", "<loc>" in r.text)
```

输出：

```
200
落点: https://blog.djdj45.top/traps/trap-python
有 <loc> 吗: False
```

把这段输出读懂，本章就懂了一半：

- 状态码 **200**——不是 403 也不是 429。**没有任何异常迹象**；
- 落点却变成了 `/traps/trap-python`——你要的是 sitemap，
  拿到的是一张警告页（Cloudflare 边缘 302 改道的）；
- 所以 `<loc>` 匹配不到。

**新手会在这里卡很久**：状态码 200、返回的是 HTML、requests 不报错、
正则匹配不到内容——他会得出"这个站没有 sitemap"的结论。
真正发生的是：**你被认出来了，而且对方没打算告诉你。**
认出你的依据还是老朋友：requests 的默认 UA（`trap-python` 这名字都在暗示）。

**你来试试**

用第 4 章的对照法：同一个 URL，带 DojoBot 身份再请求一次。

```python
r = requests.get("https://blog.djdj45.top/sitemap.xml",
                 headers={"User-Agent": "DojoBot/1.0 (+https://blog.djdj45.top/about.html)"})
print(r.status_code, "落点:", r.url)
```

输出：

```
200 落点: https://blog.djdj45.top/sitemap.xml
```

落点回来了，还是 sitemap 本尊。**同一个 URL、同一个时刻、
唯一变量是身份**——第 4 章那张对照表，在真实站点上原样成立。

## 10.2 没有信号头怎么判断 —— 落点 + 内容 = 你的信号头

**机制**

靶场被拦时给你 `X-Dojo-Block: ua`；博客什么都不给。
真实世界里判断"发生了什么"只有两个证据：

| 证据 | 问的问题 | 本章实例 |
|---|---|---|
| **落点**（`r.url`） | 我要的和到手的是同一个页面吗？ | sitemap.xml → /traps/trap-python |
| **内容**（`r.text`） | 到手的结构和预期一致吗？ | 没有 `<loc>`，反而有 trap 页标记 |

把它们写成一个判断函数——这就是你的"信号头"：

```python
def looks_trapped(resp):
    return "/traps/" in resp.url or "/blocked/" in resp.url
```

再验证一次这个判断的可靠性——拿一篇文章、两个身份：

```python
post = "https://blog.djdj45.top/posts/boot-log.html"

bare = requests.get(post)
good = requests.get(post, headers=UA)
print("裸 UA  :", bare.status_code, looks_trapped(bare))
print("DojoBot:", good.status_code, looks_trapped(good))
```

输出：

```
裸 UA  : 200 True
DojoBot: 200 False
```

裸身份拿到的 trap 页同样是 200、同样是合法 HTML——
**爬虫不会报错，只会把警告页当成文章正文存下去。**
如果不是先写好了 `looks_trapped()`，这页 HTML 就混进你的数据了。
第 6 章的教训换了个马甲又来一遍：**这次连"假数据"都不是，是"反爬的警告函"**，
但它同样会被你当正文入库——除非你先断言。

**你来试试**

打印裸身份那次的 `bare.text[:200]`——trap 页源码里有一个
`data-client-id=` 属性（它记录了把你认出来的依据）。
找到它，看看对方认出的 UA 是不是 `python-requests`。

## 10.3 综合实战 —— sitemap → 15 篇 → 入库

把全书的技能串成一条流水线。每一步用到的都是前面章节的零件：

```python
import re
import requests

BLOG = "https://blog.djdj45.top"
UA = {"User-Agent": "DojoBot/1.0 (+https://blog.djdj45.top/about.html)"}

# ① 声明身份，拿真正的清单（第 4 章：身份是自变量）
sm = requests.get(BLOG + "/sitemap.xml", headers=UA)
assert not looks_trapped(sm), "被改道了，先处理身份问题"

# ② 从 sitemap 解出文章清单（第 2 章：先数数）
posts = re.findall(r"<loc>(https?://[^<]*?/posts/[^<]+)</loc>", sm.text)
print("清单:", len(posts), "篇")          # 预期 15

# ③ 逐篇抓取（第 5 章：礼貌节奏；第 3 章：先断言行数再取字段）
import time
titles = []
for url in posts:
    r = requests.get(url, headers=UA)
    assert r.status_code == 200 and not looks_trapped(r), url
    m = re.search(r"<h1[^>]*>(.*?)</h1>", r.text, re.S)
    titles.append(re.sub(r"<[^>]+>", "", m.group(1)).strip())
    time.sleep(0.5)                        # 礼貌：别打太快
print("入库前体检:", len(titles), "篇、无空标题:", all(titles))
```

输出：

```
清单: 15 篇
入库前体检: 15 篇、无空标题: True
```

15 篇全部到手。把它们交给第 9 章的 `store()` 落库（slug 从 URL 里取，
正文从 `<article>` 段落里取——第 3 章的选择器功夫），

```
① 首次入库: (15, 0, [])
② 重跑一遍: (0, 15, [])
```

幂等依旧成立。**从裸请求到可复现的数据库，全书每一章都在这条流水线上**：

| 步骤 | 用到的章节 |
|---|---|
| 声明身份 | 第 4 章 |
| sitemap 清单 + 先数数 | 第 2 章 |
| trap 判断（落点+内容） | 第 6 章 + 本章 |
| 逐篇抓取 + 礼貌节奏 | 第 3、5 章 |
| 解析标题正文 | 第 3 章 |
| 幂等落库 | 第 9 章 |
