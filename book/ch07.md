## 7.1 现象：行数 = 0

**90 秒现象**

第 3 章的解析脚本，一个字不改：

```python
import requests
from bs4 import BeautifulSoup

r = requests.get("http://127.0.0.1:8000/")
print(r.status_code, r.headers.get("X-Dojo-Signal"))

soup = BeautifulSoup(r.content, "lxml")
rows = soup.select("ul li")
print("行数:", len(rows))
```

输出：

```
200 js-shell
行数: 0
```

200、页面正常、HTML 拿到了——**行数是 0**。第 3 章的纪律立刻接管：
0 行就停，然后排查。两个嫌疑人：

1. 选择器写错了？——把第 3 章的脚本对着 L0 的页面跑一遍，6 条；
   同一个选择器，不可能这一章突然失效。排除。
2. 页面根本不是同一张？——看正文：

```python
print(soup.get_text("\n", strip=True)[:200])
```

输出：

```
crawler-dojo / DOJO-1
DOJO-1 调试笔记
该列表由页面脚本在浏览器中构建
Loading…
这个页面需要执行 JavaScript 才能显示列表。
```

页面自己招了：**"该列表由页面脚本在浏览器中构建"**。`<ul>` 是个空壳，
条目要等浏览器执行完 JavaScript 才会填进去。requests 不执行 JS——
它拿到的永远是"填空之前的试卷"。

再确认一件事：顺手打一下第 2 章的 JSON 接口：

```python
print(requests.get("http://127.0.0.1:8000/api/articles").status_code)
```

输出：

```
404
```

也关了。后路被切断——这一级就是要逼你面对"HTML 里没有数据"。

**你来试试**

打印 `soup.body.get("data-shell")`（一个标着"我是空壳"的标记属性），
再数数 `soup.find_all("script")` 有几个——**线索就藏在这几个标签里**。

## 7.2 查数据源 —— 先找入口，别急着上浏览器

**机制**

看到"需要执行 JavaScript"，很多人的第一反应是：上 Playwright 渲染。
**那是最后手段，不是第一手段。** 正确的排查顺序：

1. **读 HTML 里的线索**——`script src`、内联 JSON、注释；
2. **找有没有现成的接口**——前端在背后请求的 JSON 接口，有时文档里根本没写；
3. 以上都没有，才上浏览器。

第 1 步的答案，7.1 的你来试试已经给出来了：

```python
print([s.get("src") for s in soup.find_all("script") if s.get("src")])
```

输出：

```
['/static/dojo-data.js']
```

页面引用了一个外部脚本。**下载它**——不用浏览器，requests 就行：

```python
pl = requests.get("http://127.0.0.1:8000/static/dojo-data.js")
print(pl.status_code, len(pl.text))
print(pl.text[:200])
```

输出：

```
200 3649
// crawler-dojo · L4 载荷。列表页的条目由它构建。
window.DOJO_ARTICLES = [
  {
    "slug": "dojo-01-baseline",
    "title": "DOJO-1 基线读数：先确认它没坏",
    "published_at": "2026-03-04",
    ...
```

数据就在里面，而且是一个普通的文本文件。浏览器做的事——下载这个文件、
执行赋值、把数组填进 DOM——每一步都可以拆开自己做，
而**第一步（下载文件）requests 就能做**。

**你来试试**

在浏览器里打开这个页面，按 F12 → Network 面板 → 刷新，
找到 `dojo-data.js` 那一行。你刚才用 requests 做的事，
就是浏览器在做的事——看清这一点，"渲染"就不再神秘。

## 7.3 `json.loads()` —— 数据藏在脚本标签里

**它是什么**

```python
json.loads(字符串) → Python 对象
```

把**字符串**解析成 Python 对象。它和第 2 章 `r.json()` 的分工：
`r.json()` 是"响应本身就是 JSON"时的捷径；`json.loads()` 吃任何字符串——
比如一个 JS 文件里的一段文本。

**最小例子**（把载荷变成数据）：

载荷的形状是 `window.DOJO_ARTICLES = [ ... ];`——前面有个变量赋值，
不是纯 JSON。先把数组部分抠出来：

```python
import json
import re

m = re.search(r"=\s*(\[.*\])\s*;", pl.text, re.S)
data = json.loads(m.group(1))
print("条数:", len(data))
print(data[0]["title"])
print(sorted(data[0].keys()))
```

输出：

```
条数: 6
DOJO-1 基线读数：先确认它没坏
['body', 'published_at', 'slug', 'summary', 'tags', 'title', 'word_count']
```

6 条，字段和第 2 章的 JSON 接口一字不差——**同一批数据，换了个货架**。

**会怎么摔（本章摔跤点）**

上面那行正则是这段代码里最脆的部分，故意留着它就是要你看清边界：

- 载荷格式一变（比如 `let` 开头、结尾没有分号、数组里带了注释），
  `m` 就是 `None`，然后 `m.group(1)` 抛出
  `AttributeError: 'NoneType' object has no attribute 'group'`——
  又见面了，还是 3.4 那个"对 None 调方法"。
- 更糟的情况：正则匹配到了**错误**的区间，`json.loads` 抛
  `json.JSONDecodeError`。这个报错倒是好读：它会说第几个字符、期望什么。

所以生产代码的正则解析 JS 一律当**临时方案**：载荷格式是你观察出来的、
不是对方承诺的，对方改一版前端你的正则就死。稳妥的优先级永远是：
先找 JSON 接口 → 再解析载荷 → 最后才考虑执行别人的代码（7.4）。

**你来试试**

把 `data` 和第 2 章基线卡对一遍：6 条、slug 形状、日期范围、字数范围——
全部对上。然后想想：如果哪天靶场把载荷改成压缩过的一行（无空格无换行），
你的正则还匹配得到吗？改改看。

## 7.4 浏览器是最后手段 —— 用代价差证明

**机制**

什么时候**必须**上浏览器？三类场景：

- 数据由 JS **算出来**，不在任何文件里（地图、动态报价）；
- 需要**交互**才出现（点击、滚动、登录之后）；
- 站点对无浏览器特征的请求直接拒绝，而你确认了合规、必须拿。

什么时候**不该**上？——只要存在接口或静态载荷（本章的情况）。
差距有多大？实验 08 把同一件事做两遍并排计时：读文本载荷 vs
启动 Chromium 渲染。它需要额外安装（Chromium 约 150 MB）：

```bash
pip install playwright && playwright install chromium
```

装好后跑 `python main.py --chapter 7`，没装时的输出本身就是教材：

```
7   07 L4：HTML 没数据 → 读脚本载荷             L4    通过  HTML 0 条 → 载荷 6 条（未启用浏览器）
7   08 L4 对照：浏览器渲染的代价                L4    跳过  跳过

── 跳过 1 项 ──
  08 未安装 playwright —— pip install playwright && playwright install chromium
```

注意**主实验 07 的结论行**：`HTML 0 条 → 载荷 6 条（未启用浏览器）`——
这一章的目标在不启动浏览器的情况下完成了。装上 playwright 再跑一次，
你会得到两个毫秒数的对比（文本请求几十毫秒 vs 浏览器渲染几百毫秒到几秒，
通常差一个数量级以上），以及一句更扎心的备注：
那个倍数还没算 150 MB 的首次下载，也没算浏览器在 CI 里偶发挂掉的重试。

**正确姿势**（把顺序刻进肌肉记忆）：

```
接口 → 静态载荷 → 浏览器。别倒过来。
```

**你来试试**

跑一遍 `python main.py --chapter 7 --verbose`，看实验 07 的完整过程：
它先确认空壳标记、数出 0 行、找到脚本、下载载荷、解出 6 条——
每一步都和你本章做的一样。框架实验和手写脚本，思路是同一套。

### 进阶（可选）

还有更难的一档：数据由代码**现场算出来**，任何一个文件里都找不到。
那时"找入口"不管用了，正解是在无头环境里把那段代码跑一遍——
但那已经不是"选哪个数据源"，而是"要不要执行别人的代码"，是另一课。
