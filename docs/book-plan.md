# 全书教学细化方案（book-plan）

> 2026-09-26 定稿方向：**形态是一本书（教程为主）**，读者是**零基础小白**。
> 教学粒度：**从每个函数开始教**。本文是全书的教学逻辑总纲——章节怎么分组、
> 每节怎么写、每个函数放在哪一节出现、动手环节长什么样。
> 工程设计辩护（契约驱动/快照/身份正交）不在这里，见 README 与 fixtures/README。

---

## 1. 读者画像与总目标

- 会一点点 Python（变量、if、for、函数调用），但没写过"完整的小项目"
- 不懂 HTTP，没听说过反爬
- 总目标：读完能独立写一个**礼貌、可校验、能落地**的爬虫，并理解守方在想什么

**一句话教学原则：每节只引入一个新函数/新属性，读者每学一个就动手用一次。**

---

## 2. 全书分五大部分

| 部分 | 章 | 读者跨过的坎 | 结束时能做到 |
|---|---|---|---|
| **I 第一性：网页就是数据** | 1–3 | "请求→响应→解析"这条最小闭环 | 抓到靶场文章并打印成表 |
| **II 身份：爬虫的自我介绍** | 4–6 | "我是谁"是唯一自变量；被拦、被限速、被骗各经历一次 | 能写带身份、会退避、能识破假数据的爬虫 |

| **V 真实世界：攻与守** | 10–12 | 真站、守方视角、合规边界 | 完整爬完博客 + 能给自己的站加防护 |

每部分开头有一页"本部分地图"：这张表 + 一句"读完你将能______"。

## 3. 两种固定模板（全书只许这两种颗粒度）

### 3.1 章的六环节（顺序固定）

```
① 90 秒现象   读者亲手跑命令，看见它失败/成功
② 发生了什么  机制讲解 ≤3 段 + 1 个比喻
③ 你来试试    改一个参数 → 先写预测 → 运行 → 对照（无答案，运行结果就是答案）
④ 正确姿势    给方法 + 一条断言钉住结论
⑤ 过关检查    python main.py --chapter N 输出与书中一致即过关
⑥ 进阶（可选）
```

### 3.2 节的"函数卡"（每节 = 一个函数/属性/方法）

```
【它是什么】一句话 + 签名
【最小例子】≤5 行可运行代码 + 预期输出（逐字给出）
【参数】    只讲本阶段要用的 1–2 个；其余参数列名字，标注"先不管，第 N 章见"
【会怎么摔】1–2 个真实 traceback 原文 + 怎么读它（读 traceback 本身就是教学）
【你来试试】一道改参数题 + 预测框
```

## 4. 逐章细化（到函数级）

### 第一部分 第一性：网页就是数据（章 1–3）

**靶场状态：`--level none`。这一章里读者只需要知道"这是一个练习用的网站"。**
**取页方式：第 1–3 章课文用裸 `requests.get`（靶场是 L0，畅通）。**
`ctx.fetch` 到第 4 章身份成为课题时才正式介绍——那时读者才有动机理解它。

#### 第 1 章 你的第一次请求

> 现象①：运行 5 行代码，屏幕上出现状态码 200 和一段 JSON。
> 本章不出现"爬虫""反爬"两个词。

| 节 | 函数卡 | 引入的概念 | 你来试试 |
|---|---|---|---|
| 1.0 | —（自查表） | 变量/列表/字典/f-string 够用检查 | 对照自查，缺哪补哪 |
| 1.1 | `requests.get(url)` | 请求就是发一条消息 | 换一个不存在的域名，预测会看到什么 |
| 1.2 | `r.status_code` | 先看门牌号再进门 | 把 URL 改成 404 路径，看状态码变几 |
| 1.3 | `r.headers`（含 `.get()`） | 信封上有信息 | 打印 3 个头，猜各自含义 |
| 1.4 | `r.content` / `r.text` / `r.encoding` / `r.apparent_encoding` | 字节怎么变文字；为什么 r.text 会乱码 | 故意用错编码解码中文 |
| 1.5 | `r.json()` | 一条命令拿结构 | 对一个 HTML 页调 `.json()`，读那个 ValueError |
| 1.6 | 综合 | 把契约 JSON 的 endpoints 打印成清单 | 过关检查 |

摔跤点设计：1.4 的乱码、1.5 的 `ValueError`——**这两个 traceback 全书后文还会反复引用**，第一次就要教读者怎么读。

#### 第 2 章 裸爬：拿到第一批数据

| 节 | 函数卡 | 你来试试 |
|---|---|---|
| 2.1 | 复习拼装：1.1–1.5 凑一个"抓列表"脚本（给残缺版让读者补三行） | 补全并运行 |
| 2.2 | `len()`：先数数 | 数一下列表里有几条 |
| 2.3 | `a["slug"]` vs `a.get("slug")`：KeyError 第一课 | 访问不存在的键，读 traceback |
| 2.4 | 列表推导式 `[a["title"] for a in items]` | 写一行取所有日期 |
| 2.5 | for + 累积：打印标题表格 | 加一列正文长度 |
| 2.6 | **基线思想**：把"正常长什么样"记下来（条数/slug 形状/日期范围） | 填一张基线记录卡（第 6 章的伏笔，务必存档） |

#### 第 3 章 解析：网页不是 JSON

| 节 | 函数卡 | 你来试试 |
|---|---|---|
| 3.1 | —：为什么真实站点常只有 HTML | — |
| 3.2 | `BeautifulSoup(html, "lxml")` | 换成 `"html.parser"`，对比行为差异 |
| 3.3 | `soup.select("css 选择器")`：返回**列表** | 写 3 个选择器，先预测各返回几行 |
| 3.4 | `soup.select_one(...)`：返回一个**或 None** | 用一个必然 miss 的选择器，看 None 从哪炸出来 |
| 3.5 | `get_text(strip=True)` | 去掉 strip 看差异 |
| 3.6 | **纪律：先断言行数再取字段**（0 行 = 选择器错或数据不在 HTML——第 7 章伏笔） | 故意写错选择器，验证自己的检查逻辑接得住 |
| 3.7 | 综合：标题+日期拆出来 | 过关检查 |

离线技能一句话版在本章出现："调选择器不用起服务，抓一份快照"——细节进附录，不展开。

### 第二部分 身份：爬虫的自我介绍（章 4–6）

**取页方式从这里起换成 `ctx.fetch(url, identity=...)`，动机就是本章课题本身。**

#### 第 4 章 403：你被认出来了（全书第一次失败）

| 节 | 内容 | 函数卡 | 你来试试 |
|---|---|---|---|
| 4.1 | 现象：裸 UA 请求 → 403（正式介绍三种身份与 ctx.fetch：它就是 requests.get 加了一个身份参数，还能离线跑） | `ctx.fetch(url, identity=...)` | 三种身份各跑一次，填对照表 |
| 4.2 | `headers` 参数：请求头是自我介绍 | 函数卡 `requests.get(url, headers=...)` | 自己编一个 UA，预测靶场的反应 |
| 4.3 | 机制：黑名单怎么工作（levels.json 的 block 列表是公开的——开卷考试） | — | 对照列表找 3 个会被拦的 UA |
| 4.4 | 伪装 vs 声明：同一个 200，两种待遇（`X-Dojo-Allow`） | — | 用伪装身份找响应头，确认拿不到白名单标记 |
| 4.5 | DojoBot/1.0 (+联系方式) 的写法与礼仪 | — | 给自己的爬虫起名并声明 |

#### 第 5 章 429 与 Retry-After：被限速了

| 节 | 函数卡 | 你来试试 |
|---|---|---|
| 5.1 | 现象：连续请求被限流（本章 live_only——限流是时间维度的现象，快照替代不了，理由写明） | 连发 20 个请求看第几个开始 429 |
| 5.2 | `r.headers["Retry-After"]`：服务端在告诉你等多久 | 读出那个数 |
| 5.3 | `time.sleep()`：最笨也最有效 | 按 Retry-After 等待后重试 |
| 5.4 | 指数退避 2s→4s→8s | 写 `retry_get(url, max_tries=3)` |
| 5.5 | 抖动为什么比退避更重要（同步重试 = 二次洪峰） | 给 retry_get 加 `random.uniform` |

#### 第 6 章 200 也可能是假的：蜜罐（全项目唯一"成功了却毫无用处"）

| 节 | 函数卡 | 你来试试 |
|---|---|---|
| 6.1 | 现象：200、结构完整、字段齐全，但每条都是假的 | 对比 L0 与 L3 两份快照的第 1 条 |
| 6.2 | 四种机械可判的校验：日期范围 / 重复率 / 链接可达 / 字段自洽 | 每种先口述判断标准 |
| 6.3 | `datetime.date.fromisoformat()` + 日期比较 | 用第 2 章基线卡验证日期异常 |
| 6.4 | `set()` 判重 | 算标题重复率 |
| 6.5 | 基线回归：第 2 章那张卡现在是武器 | 把四个校验组装成一个 `is_trustworthy(article)` |

### 第三部分 硬骨头（章 7）

| 节 | 函数卡 | 你来试试 |
|---|---|---|
| 7.1 | 现象：`li 行数 = 0`（第 3 章埋的伏笔爆发） | 确认不是选择器写错 |
| 7.2 | 查数据源：浏览器 Network 面板 / 找到 `/static/dojo-data.js` | 自己找到那个文件 |

### 第四部分 工程（章 8–9）

**第 8 章 Scrapy：框架帮你做了什么、又瞒了你什么**——Spider/Item/Pipeline 最小版、中间件在哪一层改请求、五个"跑了才知道"的框架行为（`start_requests` 不被调用且不报错等）。你来试试：给 pipeline 加一列正文字数。

**第 9 章 落地：数据要能重复入库**——`sqlite3`（或 SQLAlchemy）连接与建表、**幂等 upsert**（跑两遍结果一样）、**拒收留痕**（rejected 表，不静默丢弃）、CSV/JSON 导出。你来试试：把蜜罐数据拒之门外并留痕。

### 第五部分 真实世界（章 10–12）

- **第 10 章 真实战场（博客）**：连 sitemap 都被改道（默认 UA）→ 带身份重来 → 15 篇入库。综合运用 II 部分全部技能。
- **第 11 章 写防护：坐到对面去（守方视角）**——**lab10（时效签名）从第 8 章挪到这里**。三个先回答的问题 → WAF/限流/中间件（博客真实案例）→ `hmac` 函数卡：签名该签什么 → 什么时候停手（反面清单）。
- **第 12 章 合规边界与综合实战**：robots.txt、频率礼仪、法律边界、完整合规爬取博客收官。

## 6. 写作纪律（每章动笔前对照）

- 每节一个新函数，宁可拆章不合并
- 所有 traceback 逐字真实（跑出来再抄，不凭记忆编）
- 比喻每个概念最多一个，用完即弃
- "你来试试"必须能靠运行结果自行验证，不依赖标准答案
- 伏笔显式管理：3.6 → 7.1，2.6 → 6.5，4.4 → 11.3
- 工程辩护（为什么契约驱动、为什么快照）一律不进正文，进附录/开发文档
