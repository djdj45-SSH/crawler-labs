# 开发设计备忘（dev-design）

> 这里放**工程设计的辩护与机制细节**——它们解释"这套实验设施为什么这样建"，
> 面向的是维护者/贡献者，不是读者。
> 课文正文不出现这些内容（写作纪律见 `book-plan.md` §6）；README 只保留入口。

## 1. 契约驱动：为什么规则不复制一份

爬虫侧不写任何"第几级是什么"的知识，全部从 `GET /__dojo/contract` 拉。

因为把规则在两处各写一遍，**它们一定会漂移** —— 改了靶场忘了改爬虫，
你跑出错误结论，然后会以为是自己的代码写错了。

- 契约一旦拉到就落盘 `fixtures/contract.cache.json`，靶场没起也能读缓存。
- 契约里带 `runtime.active_levels`，直接告诉你当前实际生效的是哪几级
  —— 不必猜，也不存在"我以为开的是 L3"这种歧义。
- 唯一事实来源是 `crawler-dojo/levels.json`。加一级防护 = 改它 + 加一个 guard，
  爬虫仓库一行不用动。

## 2. 快照：离线能力的全部机制

- `snapshot.py --all`：自己起靶场、六个等级各抓一份、写 manifest、关掉。
- 索引键是 **(路径, 身份)** —— 少了身份，第 4 章的对照就无从复现。
- `manifest.json` 冻结抓取时的**完整契约** → 离线模式直接拿它当契约用，
  `require()` / `ensure_level()` 的判断逻辑**一个字不用改**。
  两个消费者：`main.py --snapshot` 与 `scrapy -s DOJO_SNAPSHOT=`，改格式要一起想。
- **内容层与防护层正交**：白名单身份拿到的内容在任何等级下都一样。
  所以第 2、3 章的页面随便哪份快照都能跑；第 4、6、7 章看的是防护层，必须对应等级那份。
  这也解释了为什么**离线比在线 `--level all` 能多跑通两项**（叠加防护下裸 UA 在 L1 就被拦）。

已知性质（不是 bug）：
- 快照会过期。尤其 `l3`：蜜罐假日期相对"抓取当天"生成，放十几天 F1 自然失效。
  `lab06` 离线模式改用快照抓取日做基准规避；长期用就 `snapshot.py --all --force` 重抓。
- 在 L2 下抓快照，抓取动作本身会被限流。`snapshot.py` 按契约算安全间隔自动放慢
  （`window/(limit-1)` 再留 15% 余量）。

## 3. 取页面只有一条路：`ctx.fetch(url, identity=...)`

实验室代码一律走 `ctx.fetch`，不要直接 `requests.get`——
同一段解析代码能对实时靶场跑也能对快照跑，这是整本书可复现的前提。

- 三类身份 `bare` / `browser` / `whitelist` 定义在 `dojo.py`（`IDENTITIES` + `headers_for`），
  **抓取侧与读取侧共用一套**，不许各写一份（快照索引键含身份，两边理解不一致就对不上）。
- `identity` 是 `ctx.fetch` 的显式必填参数：少了它，"伪装 vs 声明身份"的对照无从复现。
- 真正离不开实时请求的实验显式声明 `live_only = True` + 理由（现在是 4 个：
  第 5 章限流、实验 08 渲染耗时、第 11 章签名验签、第 10 章真实站点）。
  离线模式下它们跳过并打印理由，不是静默消失。
- 第 8 章的 Scrapy 侧是同一条规则的另一种写法：下载器中间件
  （`dojo_spider/snapshot.py`）在 `process_request` 里直接返回冻结响应——
  spider、items、9 个管道一行没改，输出逐字相同。

## 4. 章节映射的机械事实

- 实验→章的对应关系由每个 lab 的 `chapter` 字段声明（唯一来源）。
- **lab10（时效签名/L5）属于第 11 章守方线**，2026-09-26 起生效；
  `labs/__init__.py` 的 `LAB_CLASSES` 顺序 = 章节顺序，改章号要同步挪位置。
- `main.py --chapter N` 按 `chapter` 字段过滤；第 8 章（Scrapy）与第 12 章（综合）
  没有矩阵实验，走 `CHAPTER_GUIDES` 提示跑法。
- 靶场等级在启动时装配（`--level X`），不支持热切换；L0 没有 guard——它是"无防护"这个状态。

## 5. 已知的环境坑

- **代理**：`http_proxy` 环境下 requests 会把 `127.0.0.1:8000` 也发给代理，
  拿到代理的错误响应（502/空响应/缺信号头），看起来像"靶场坏了"。
  `dojo.py` 导入时把 loopback 补进 `no_proxy`；自己写脚本记得同样处理。
- **Playwright 可选**：实验 08 跳过并打印安装命令；Chromium 约 150 MB。
- **Scrapy 框架行为**（`scrapy_dojo/README.md` 有完整五条）：2.19 里 `start_requests()`
  完全不被调用且不报错；spider 的契约加载必须在 `start()` 不能放 `__init__`
  （那时读不到 `-s`）；下载器中间件优先级见 `settings.py` 注释（540 排在 UserAgentMiddleware 500 之后）。

## 6. 运行器（main.py）的行为约定

- 跳过 ≠ 失败：前提不成立时跳过并说明怎么补前提；**绝不在错误前提下报成功**。
- `--chapter N` 的读者宽容：靶场没起且本地有快照 → 自动改离线并打黄字提示；
  无快照才报错。普通模式（无 `--chapter`）行为不变，保持显式。
- exit code：有失败 = 1，其余 = 0（CI 友好）。
